# PharmEasy Regional Pulse

A single, repeatable pipeline that takes PharmEasy's raw monthly order
export for the Telugu-states regional desk (Telangana, Andhra Pradesh,
and the Bengaluru hub), cleans and validates it, computes SQL-verified
region/month performance metrics, flags regions that moved enough to
matter, drafts a reviewable insight narrative and one-page
recommendation memo, routes every draft through a human
approve/edit/reject gate with an audit trail, and presents everything
through a local interactive Streamlit dashboard with an
audience-framed presentation storyline.

## How to run the whole pipeline end-to-end

Requires Python 3.10+. No API keys, no paid services, no signup-gated
tools — everything runs locally with open-source libraries.

```bash
# 1. Install dependencies
pip install -r requirements.txt

# 2. Run the whole pipeline: dataset generation -> cleaning -> metrics
#    -> report/review, each stage consuming the previous stage's output
python3 run_pipeline.py

# 3. Launch the dashboard
streamlit run app.py
```

`run_pipeline.py` simply runs the individual stage scripts below in
order and stops immediately if any stage fails, so you can also run
any stage on its own:

```bash
python3 generate_dataset.py   # Part 1 -- raw dataset
python3 clean_data.py         # Part 1 -- cleaning + validate_schema
python3 build_db.py           # Part 2 -- pharmeasy.db
python3 queries.py            # Part 2 -- JOIN validation + metrics
python3 metrics_engine.py     # Part 2 -- flagging + state persistence
python3 draft_report.py       # Part 3 -- CII draft report
python3 review_gate.py        # Part 3 -- review-gate test harness (writes audit_log.jsonl)
streamlit run app.py          # Part 4 -- dashboard
```

### What each command does

| Command | What it does |
|---|---|
| `python3 generate_dataset.py` | Deterministically (seed 2026) writes `pharmeasy_orders_raw.csv` (2159 rows) and `regions_master.csv` (10 regions). |
| `python3 clean_data.py` | Removes 59 exact duplicates, normalizes region names, imputes missing `category`/`profit_inr`, writes `orders_clean.csv` (2100 rows), and demonstrates `validate_schema()`. |
| `python3 build_db.py` | Loads the clean data into `pharmeasy.db` (SQLite) as `regions_master` and `orders_clean` tables. |
| `python3 queries.py` | Runs and prints all JOIN-validation checks (row counts, duplicate-key check, `COUNT(*)` vs `COUNT(order_id)`, per-region order counts) plus region×month sales and MoM growth. |
| `python3 metrics_engine.py` | Computes % change, flags significant regions (±8% threshold), and demonstrates state persistence round-tripping via JSON. |
| `python3 draft_report.py` | Generates one Context–Insight–Implication block per flagged region (8 unique regions across both transitions). |
| `python3 review_gate.py` | Test harness exercising `approve` / `edit` / `reject`, writing to `audit_log.jsonl`. |
| `python3 run_pipeline.py` | Runs every stage above in order in one command, stopping immediately if any stage fails. |
| `streamlit run app.py` | Launches the 3-level dashboard (Overview → Category → Detail) with an embedded executive summary and a live CII narrative generated by `draft_report_v1()`. Each block sits behind a real Approve / Edit / Reject control with a reviewer-note field — nothing is auto-approved; `review_gate_v1()` only fires (and logs to `audit_log.jsonl`) when a human clicks a decision. |

## Cover note — four artifacts, one package

**Headline finding:** Guntur's total sales swung +122.19% from April
to May 2026, then partially retraced (−28.11%) in June — the single
largest-magnitude region movement in this dataset, verified by SQL
against a deduplicated, schema-validated order table.

**The four artifacts and what each is for:**

1. **The Streamlit dashboard** (`app.py`, run via `streamlit run app.py`) — live data exploration: KPI cards, category breakdown, and a per-region/per-month detail table, all connected by one region filter.
2. **The CII narrative** (embedded in the dashboard, generated live by `draft_report_v1()` — not retyped by hand — and held behind a real Approve/Edit/Reject reviewer control in `app.py`; `review_gate_v1()` only runs when a human clicks a decision) — what the data means: a Context–Insight–Implication read of the flagged regions in plain language.
3. **The one-page memo** (`memo.md`) — the recommendation: what to check next in Guntur and why, with every claim risk-tagged `[LOW]`/`[MEDIUM]`/`[HIGH]`.
4. **The presentation storyline** (`presentation_storyline.md`) — how to defend it live: the same Guntur finding reframed for an executive (Situation–Complication–Resolution) and a regional manager (Overview–Category–Detail), plus anticipated pushback Q&A.

**Recommended consumption order:** dashboard → embedded CII narrative
→ `memo.md` → `presentation_storyline.md` — see the numbers first,
then the interpretation, then the recommendation, then how to present
and defend it.

**Single unverified assumption to flag upfront** (from `memo.md`'s
Assumptions field): this pipeline assumes the sales and profit
figures in the raw monthly export are themselves accurate at the
point of entry — the cleaning pipeline fixes duplicates, inconsistent
region names, and missing category/profit fields, but cannot detect
or correct an order that was entered with a wrong price or quantity
in the first place.
